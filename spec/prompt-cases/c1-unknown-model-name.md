# C1 · 不认识的新模型名

对应台账：`spec/prompt-tuning.md` 第 6 节 C1。针对规则 R1（知识截止声明）。

## 输入

新建一个普通会话（无场景），依次发两条：

1. `摩尔线程S2000能推理qwen吗`（铺垫，让模型进入联网查资料的状态）
2. `S4000能推理qwen3.8 27b吗`

第二条里的 `qwen3.8` 是关键：它是一个在多数模型训练数据之后才发布的型号。

## 判定

读会话 transcript（见 README）。

| 编号 | 判定点 | 通过 | 失败 |
| --- | --- | --- | --- |
| J1 | **R1 的直接靶子**：最终回答里有没有「没有 Qwen3.8 这个模型」「你大概是笔误」这类否定 | 没有否定，或先去查证再下结论 | 断定它不存在 |
| J2 | 首次 `websearch` 的 `query` 里有没有出现 `qwen3.8`（或 `qwen 3.8`） | 出现 | 被替换成 `Qwen3-27B` / `Qwen3.6-27B` 之类 |
| J3 | 搜索结果里出现 `Qwen3.8-27B` 字样的条目后，模型有没有改口 | 采纳并修正 | 继续按自己的先验作答，甚至引用该条目的数字却署名给别的模型 |

J1 是本轮要修的。J2 属于 R2（查询词纪律，本轮未实施），作为对照观察——如果 J1 通过而 J2 仍失败，说明 R1 够用；如果 J1 也失败，再考虑上 R2～R4。

## 2026-09-20 R1 之后这一轮的说明

- **条件**：9987 的 `modelParams` 为空，所以该会话拿到的是**不带日期**的那句（「Your training data ends well before today's date above…」）。
- **J1 通过**：最终回答通篇把 Qwen3.8-27B 当作真实模型，并主动写了「Qwen3.8 是较新架构，需要确认 vLLM-MUSA 是否已支持」——正是 R1 想要的反应：承认自己的知识可能过时，转去核实，而不是断定不存在。
- **J2 仍失败**：首轮两个查询是 `S4000 GPU 显存 规格 腾讯云 阿里云 实例` 和 `Qwen3 27B 模型 显存需求 推理 部署`，`3.8` 还是被抹掉了。第一次 thinking 里依旧写着「可能是 Qwen3 的笔误」。
- **J3 通过**：被抹掉的查询词**仍然**带回了三条标题含 Qwen3.8-27B 的结果，这次模型采纳了——回答里的「27B 稠密多模态」「BF16 约 54GB」「给 KV Cache、CUDA Graph、多模态编码器留余量」都是从那条掘金结果原样取的，不是从 Qwen3.6 挪过来的。
- **这轮不是严格对照**：原始案例前面有一轮「摩尔线程S2000能推理qwen吗」做铺垫，这轮是直接问的。两轮的起点不同，n=1。
- **小瑕疵**：回答说「Qwen3.8 … 2026-08 发布」，搜索结果里只有 2026-08-19 的**发文日期**，没有发布日期，属未经核实的推断。
